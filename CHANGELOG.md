# История изменений

Здесь фиксируются завершённые этапы проекта: что стало доступно пользователю, какие решения приняты, что проверено и какие ограничения остаются. Новые записи добавляются сверху. Подробные изменения файлов сохраняются в истории Git; инструкция по запуску находится в [README.md](README.md).

## 0.2.3 — 2026-11-11

- Библиография выводит название, авторов и данные публикации отдельными строками. Год стоит в конце в скобках. Ссылка ведёт на доступный по записи PDF, arXiv, подтверждённую страницу издателя или DOI.
- «Фокус внимания» влияет на обзор и утверждения. Отдельные вопросы получают ответы в раскрывающемся блоке. Обзор содержит до двух абзацев и словарь терминов. Основные утверждения раскрываются до пояснения и подтверждающего фрагмента.
- В основной библиотеке видны авторы и доступна исходная аннотация. Кнопка «Задания по этой статье» открывает историю с фильтром, а пункт «Задания» в меню показывает общую историю.
- Для статьи arXiv сохраняется определённый основной исходник той же версии. Кнопка «Открыть исходник .tex» показывает TeX с подсветкой и скачиванием. Исходник Word сохраняется в папку статьи. Извлечённый текст остаётся в локальном `text.txt`.
- Сохранённые профили обновляются из локальных файлов при запуске. Для добавления доступного исходника к уже подготовленной статье arXiv достаточно обновить её из профиля.
- Сохранение профиля повторяет переименование временной папки после кратковременного отказа доступа Windows.

## 0.2.0 — 2026-11-10

- Получение последней версии arXiv по ссылке или ID и обработка загруженных PDF. Извлечённый текст привязан к страницам, а пробелы извлечения отмечаются в профиле.

- Сохранение истории заданий 0.1 и объединение строк одной публикации arXiv. Демонстрационный режим по-прежнему доступен.
- Подключение OpenAI Responses API с ключом из окружения. Есть лимиты на время, число вызовов и объём запроса и ответа. Фактически сообщённые токены видны в задании.
- Интеграционные сценарии для загрузки PDF, разрешения версии arXiv, обработки и обновления профиля, остановки во время вызова, восстановления файлов после прерывания и миграции истории.

## 0.1.0 — 2026-11-05

### Этап 1: локальный прототип с демонстрационным обработчиком

Цель этапа — пройти пользовательский сценарий от добавления статьи до сохранённого отчёта и проверить управление заданиями до подключения научного агента.

### Добавлено

- Локальный HTTP-сервер на Python и русскоязычный HTML/CSS/JavaScript-интерфейс: «Новый разбор», «Задания», «Библиотека», «Настройки».
- Приём ID и ссылок arXiv, включая явно указанные версии, и загрузка PDF до 15 МБ. PDF сохраняются локально; одинаковые файлы объединяются по SHA-256 содержимого.
- SQLite-хранилище материалов, настроек, заданий, журнала этапов и отчётов. Каждое задание получает отдельный снимок настроек.
- Последовательная фоновая очередь с пятью имитируемыми этапами: получение материалов, выделение утверждений, поиск предшественников, проверки, подготовка отчёта.
- Отображение состояния и прогресса, остановка задания пользователем, демонстрационная ошибка на этапе поиска и ограничение времени обработки.
- Продолжение обработки после закрытия браузерной вкладки, пока сервер работает. После перезапуска сервера незавершённые задания сохраняются как прерванные и не запускаются повторно автоматически.
- Библиотека со связанными заданиями, просмотр и скачивание демонстрационного отчёта в Markdown.
- Редактируемые научные интересы, исключения, правила, язык будущих отчётов, длительность демонстрационных этапов и лимит времени.
- Скрипты запуска `start.cmd` и `start.ps1`, инструкция по запуску и ручной проверке в README.
- Исключение рабочих данных, загруженных материалов, тестовых каталогов, локальных файлов окружения и служебных файлов Python из Git.

### Технические решения

- Для первого прототипа используются стандартная библиотека Python и SQLite вместо первоначально предложенного FastAPI. Это позволяет проверить сценарий без установки дополнительных пакетов. Переход на полноценный серверный стек оставлен для дальнейшего развития.
- Сервер доступен только на `127.0.0.1`; интерфейс не загружает внешние библиотеки и шрифты. Запросы с посторонним Host или Origin отклоняются.
- Обработчик выполняется в отдельном потоке серверного процесса. Это фоновая обработка независимо от вкладки браузера, но пока не отдельная служба.
- Ключ OpenAI API не считывается. Вызовов модели, внешних сетевых запросов и расходов API нет.

### Проверено

Пять интеграционных тестов прошли при разработке этапа:

1. Завершение задания, сохранение снимка настроек, объединение материалов в библиотеке и скачивание отчёта.
2. Последовательная очередь, остановка и сохранение истории после принудительного завершения и перезапуска сервера.
3. Демонстрационная ошибка и остановка по лимиту времени.
4. Сохранение PDF, проверка входных данных и отклонение запросов с постороннего сайта.
5. Второй экземпляр сервера на том же порту не нарушает выполняющееся задание.

После уточнения текста отчёта отдельно повторно пройден тест завершения: для arXiv отчёт указывает, что текст статьи не загружался, и не утверждает, что был сохранён PDF.

В браузере вручную проверены создание и завершение задания, отображение отчёта, сохранение настроек и переход из библиотеки к связанным заданиям. Проверены синтаксис JavaScript и PowerShell, запуск через `start.ps1` и обнаружение уже работающего сервера.

### Ограничения и следующий этап

- Научный анализ не выполняется: задержки и отчёт являются явно обозначенными заглушками. Научных выводов или оценок корректности статей прототип не даёт.
- Существование статьи arXiv не проверяется, версия без явного номера не определяется, текст статьи и приложения не скачиваются. Для загруженного PDF текст не извлекается.
- Научные настройки, вопросы и глубина сохраняются, но пока не управляют анализом модели. Демонстрационный шаблон всегда на русском.
- Подключение OpenAI, получение и разбор материалов, поиск предшественников и независимые вычислительные проверки ещё не реализованы. Тематические обзоры и мониторинг arXiv остаются дальнейшими этапами.
- Нет авторизации, удаления материалов через интерфейс и автоматического возобновления заданий. Для каждой папки данных следует запускать только один сервер. Публикация в интернете не входит в этот этап.

Следующая отдельная задача — согласовать и реализовать первый реальный путь рецензирования с явными ограничениями инструментов, времени и расходов. Этот этап сам по себе не включает подключение API.
